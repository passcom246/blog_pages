深色模式与配色实践 ​

深色模式不是把颜色反过来那么简单。这篇文章记录这个博客的配色方案，以及踩过的几个对比度坑。

先定令牌，再写样式 ​

配色最容易失控的地方是「到处写魔法值」。我的做法是：颜色只在 CSS 变量里出现一次。

css
/* theme/styles/vars.css */
:root {
  --vp-c-brand-1: #3451b2;              /* 主色：正文链接、边框高亮 */
  --vp-c-brand-2: #2b4392;              /* hover */
  --vp-c-brand-3: #24387a;              /* active */
  --vp-c-brand-soft: rgba(52, 81, 178, 0.14); /* 标签底色 */
}

.dark {
  --vp-c-brand-1: #8fa3ee;
  --vp-c-brand-2: #a7b8f3;
  --vp-c-brand-3: #c2cdf8;
  --vp-c-brand-soft: rgba(143, 163, 238, 0.16);
}

深色模式的三条规则 ​

一、浅色下越深的颜色，深色下要越浅 ​

#3451B2 放在深色背景（#1b1b1f）上，对比度大约 3:1，做正文链接是不够的。所以深色模式用它的「提亮版」#8FA3EE，对比度能到 7:1 以上。

判断标准很朴素：把页面截图转成灰度，如果链接和正文分不出来，就是对比度不够。

二、按钮不要简单地反转 ​

浅色模式下品牌按钮是「深蓝底 + 白字」。深色模式如果直接把底色换成浅蓝，白字就糊了：

浅色：#3451B2 底 + #FFFFFF 字  ✅
深色：#8FA3EE 底 + #FFFFFF 字  ❌ 对比度不足
深色：#4A63C8 底 + #FFFFFF 字  ✅ 取中间调

三、背景不要用纯黑 ​

#000000 在 OLED 屏上对比过强，长时间阅读容易疲劳，而且卡片、边框失去了层次。用 #1b1b1f 这类略带色相的深灰，边框用 rgba(255, 255, 255, 0.12)，层次就出来了。

首页背景用渐变而不是动效 ​

首页想要一点氛围感，但视频和粒子特效的代价太大：额外的网络请求、持续的 CPU 占用、移动端掉帧。

最终只用了一条静态渐变：

css
.VPHome {
  background: linear-gradient(180deg, #eef1fb 0%, #f7f8fd 42%, var(--vp-c-bg) 100%);
}

.dark .VPHome {
  background: linear-gradient(180deg, #191a26 0%, #17181e 42%, var(--vp-c-bg) 100%);
}

卡片交互：轻微上浮就够了 ​

悬停反馈只需要三件事同时发生，幅度都要小：

css
.post-card {
  transition: transform 0.2s ease, box-shadow 0.2s ease, border-color 0.2s ease;
}

.post-card:hover {
  transform: translateY(-4px);
  border-color: var(--vp-c-brand-1);
  box-shadow: var(--blog-card-shadow);
}

位移控制在 4px 以内、时间控制在 200ms 左右，反馈明确又不喧宾夺主。位移过大会让整个网格「晃」，阅读时很出戏。

小结 ​

  • 颜色收敛成令牌，组件只引用变量
  • 深色模式是「重新设计一套」，不是「反色」
  • 对比度优先于好看
  • 氛围感用静态渐变，不用动效
