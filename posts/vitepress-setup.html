用 VitePress 搭一个博客 ​

VitePress 常被当作文档工具，但它同样适合做博客：Markdown 写作、Vite 构建、Vue 组件随手可用。

为什么选 VitePress ​

选它主要看三点：

关注点VitePress 的表现
写作体验纯 Markdown，frontmatter 管理元信息
定制成本自定义主题只是「继承默认主题 + 覆盖样式」
构建性能基于 Vite，增量启动，构建产物是纯静态文件

第三点对博客尤其重要：静态产物可以直接丢给 GitHub Pages，不需要服务器。

目录约定 ​

约定俗成的结构是这样的：

docs/
├── .vitepress/
│   ├── config.mts          # 站点配置（导航、主题、Markdown 行为）
│   └── theme/              # 自定义主题
│       ├── index.ts
│       ├── styles/         # 设计令牌与全局样式
│       ├── components/     # 业务组件
│       └── posts.data.ts   # 文章数据加载器
├── index.md                # 首页
├── about.md                # 关于
├── blog/index.md           # 文章列表
└── posts/*.md              # 文章正文

用数据加载器生成文章列表 ​

手动维护文章列表很快就会失效。VitePress 提供了 createContentLoader，可以在构建时读取全部文章的 frontmatter：

ts
// docs/.vitepress/theme/posts.data.ts
import { createContentLoader } from 'vitepress'

export default createContentLoader('posts/*.md', {
  excerpt: true,
  transform(raw) {
    return raw
      .map(({ url, frontmatter, excerpt }) => ({
        url,
        title: String(frontmatter.title ?? '未命名文章'),
        date: String(frontmatter.date ?? ''),
        tags: (frontmatter.tags as string[]) ?? [],
        excerpt: excerpt ?? ''
      }))
      .sort((a, b) => (a.date < b.date ? 1 : -1))
  }
})

两个容易踩的坑 ​

日期要加引号 ​

frontmatter 里不写引号的话，2026-09-01 会被 YAML 解析成 Date 对象，之后做字符串排序会得到奇怪的结果：

yaml
# 正确
date: '2026-09-01'
1
2

摘要分隔符 ​

excerpt: true 默认截取正文第一段。如果想要精确控制摘要，可以在摘要结束处放一行 <!-- more -->。

部署到 GitHub Pages ​

构建一次，把 docs/.vitepress/dist 的内容发布到 Pages 仓库即可。用 GitHub Actions 可以自动化这一步，详见项目的部署说明。

小结 ​

VitePress 的博客方案可以概括成一句话：把复杂度留给内容，把样式收敛到令牌。
